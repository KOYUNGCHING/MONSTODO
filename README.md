# MONSTODO — 小怪獸待辦夥伴

繁體中文的單頁任務管理工具，依需求規格書實作。HTML、CSS、原生 JavaScript、SVG 與所有功能都整合在 `index.html`，不使用外部套件、字型、圖片、API Key 或後端。

## 立即使用

用 Chrome、Edge 或 Safari 開啟 `index.html` 就能開始。建議正式使用時透過固定網址開啟，讓瀏覽器穩定保存 localStorage；直接開啟檔案時，各瀏覽器對儲存的行為可能不同。

也可以在終端機執行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

在瀏覽器開啟 <http://127.0.0.1:4173>。停止伺服器時，在原終端機按 `Control + C`。

不需要 `npm install`、編譯或登入。

## 操作教學

1. 按右上角「新增任務」，填名稱、分類、截止日期與優先級。時間未填時使用 23:59，分類預設 Other，優先級預設 Medium。
2. 在表單按「新增子任務」，可設定名稱、勾選狀態或移除；空白子任務必須填寫或移除才能儲存。
3. 點任務名稱展開詳細內容與子任務；鉛筆按鈕可以編輯，叉號可以刪除。刪除前會詢問確認。
4. 勾選主任務即完成，並記錄完成時間。若有未完成子任務，會先詢問。子任務全完成不會自動完成主任務。
5. 同時使用搜尋、分類、完成狀態、優先級，縮小任務範圍。搜尋涵蓋名稱及詳細內容。
6. 切換「月曆」，使用左右按鈕切換月份，按「本月」回到今天；點日期後，下方會顯示該日任務，可直接展開、編輯、刪除或完成。
7. 側邊欄齒輪可管理分類；手機先按左上角選單。可改名稱、圖示及顏色。刪除分類時，所有原任務移至 Other；Other 不能刪除。

任務會依截止日期與時間、優先級、建立時間排序。已完成任務獨立排列在後方，以完成時間由新至舊顯示。

小怪獸會休息、微笑、緊張或擔心，滑鼠移動時眼睛會跟隨。完成主任務會歡呼約 1.9 秒，完成今日最後一個到期任務則特別慶祝。重新整理不重播。系統啟用減少動態效果時會關閉非必要動畫與眼睛追蹤。

## 統計的意思

- **待完成**：所有未完成主任務。
- **今日到期**：截止日期是今天、仍未完成的主任務。
- **已逾期**：截止時間已過且未完成的主任務。
- **今日完成**：實際在今天完成的主任務，不限定其截止日期。
- **今日任務進度**：今天到期且已完成的主任務 ÷ 今天到期的主任務總數。今天沒有到期任務時，不顯示百分比。

期限與日期每 30 秒更新，切回頁面時也會更新。所有日期使用瀏覽器的本地時間。


這份專案沒有代你建立 GitHub repository、提交、推送或發布。你準備好後可以依下列步驟自行完成：

1. 登入 GitHub，右上角 **＋ → New repository**。
2. 名稱填 `MONSTODO`，選 **Public**，啟用 **Add README**，按 **Create repository**。
3. 進入新 repository，選 **Add file → Upload files**。
4. 拖入本機 `index.html`，放在最外層；不要再包一層 MONSTODO 資料夾。只需要這個檔案，測試與說明檔不影響網站執行。
5. 輸入提交訊息，例如 `Add MONSTODO website`，儲存至 `main`。按鈕依介面可能顯示 **Commit changes** 或 **Propose changes**；若建立了分支，須合併回 `main`。
6. 開啟 **Settings → Pages**。
7. 在 **Build and deployment → Source** 選 **Deploy from a branch**。
8. **Branch** 選 `main`，資料夾選 **/ (root)**，按 **Save**。
9. 等待發布完成，Pages 畫面會顯示網站網址。通常是 `https://你的帳號.github.io/MONSTODO/`，實際以 GitHub 顯示為準。發布最久可能約 10 分鐘。
10. 開啟網址，新增一筆任務，重新整理確認仍存在，再用手機檢查。

日後更新：上傳新版 `index.html` 覆蓋同名檔案，提交至發布分支，等待 GitHub Pages 更新即可。一般不必再次設定 Pages。

若出現 404：先確認 `index.html` 全小寫且位於 repository 根目錄，Pages 使用正確分支與 `/ (root)`，再查看 repository 的 **Actions** 是否完成發布。

參考 GitHub 官方說明：[上傳檔案](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)、[GitHub Pages 設定](https://docs.github.com/en/pages/quickstart)。

## 資料保存與限制

資料存在這個瀏覽器的 localStorage，鍵名為 `monstodo.v1`。沒有帳號、雲端備份、跨裝置同步或多人協作。發布到 GitHub 只會上傳網站程式，不會上傳你的待辦資料。

同一個人換瀏覽器、換裝置，或從本機網址切換到 GitHub Pages 時，會看到各自獨立的資料。清除網站資料或使用隱私瀏覽可能造成資料消失。正式記錄重要任務前，建議先在最終發布網址開始使用。

如果儲存空間已滿或瀏覽器拒絕儲存，頁面會顯示提醒，當次操作仍可繼續，但關閉頁面可能遺失。若整份已存資料損毀，網站保留原始內容並暫停寫入，避免直接覆蓋；可先由開發者工具的 Storage / Application → Local Storage 備份原始 `monstodo.v1` 值，再修復或移除損壞的鍵。移除會清除原有任務與分類。
